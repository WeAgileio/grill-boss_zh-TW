> 拷問的不是主管，是需求本身。
> 主管不在對話裡、跑去問一次成本很高——所以它替你把問題想全、把事實查好，把只有主管能拍板的事壓成一張「10 秒勾選」的請示清單，剩下的全部自己扛。

本專案是 [onlyLT/grill-boss](https://github.com/onlyLT/grill-boss) 的**繁體中文改寫版**：核心方法沿用原版，用語改為台灣職場情境。

## 你是否也遇過

- 主管的需求只有一句話，但你交的方案要對十個沒人問過的問題負責
- 鼓起勇氣去問，得到：「你先弄個初稿看看」
- 初稿交上去：「方向不對，重寫」
- 讓 AI 幫忙寫方案？它比你更敢掰：掰數字、掰背景、掰主管的意圖

最後一條，是 grill-boss 直接治的病。

## 它怎麼做事

### 1. 需求是一棵樹，先挖樹根 🌳

主管的原話幾乎從不等於真實需求。第一輪永遠先問意圖層：為什麼**現在**提？成果給**誰**看？主管心裡「成了」長什麼樣？能動用什麼資源？——樹根錯了，上面再茂盛也是白費。

### 2. 問題三分流 🚦

| 去向 | 例子 | 處理 |
|---|---|---|
| **自己查** | 政策原文、其他單位做法、今天幾號 | 派後台代理去查，絕不打擾你 |
| **問你** | 文件格式、工具選擇、先後順序 | 直接問，每題附建議答案 |
| **問主管** | 真實目的、規格高低、預算、政治考量 | 收進請示清單，能不問就不問 |

提問按**前線分輪**：只問前置已定的問題，一輪問完、絕不擠牙膏；下游問題等上游定了再問。十三個問題，三輪問完，不是十三輪。

### 3. 請示清單：讓主管 10 秒答完 📋

不超過 5 條封閉式問題，每條給建議選項 + 一句話理由，主管掃一眼勾選即可。能用穩當預設假設兜住的問題，不配佔請示名額。清單末尾自帶保命句：

> 「若您沒空細看，我先按建議項推進，有偏差隨時糾正。」

### 4. 假設清單：不記黑帳 📒

問不到的決策，不許偷偷寫進方案——預設值、選它的依據、猜錯的代價，三欄記帳，隨方案一起交付。方案裡出現的每個數字（包括「今天星期四」）要嘛有出處，要嘛在假設清單裡。主管翻到那一頁，看到的不是漏洞，是你把風險都想到了。

### 5. 「急」不是跳過的理由 ⏰

你說「很急，別問了」，它不會從此閉嘴亂掰——只會把提問壓縮成一輪，問完最要命的 3–5 題，其餘全部改成明確假設。快，但不瞎猜。

## Before / After

**沒有 grill-boss：**

> 「好的！以下是《XX 工作方案》：預計提升效率 40%，核心職位涵蓋率達 80%……」
>
> （這些數字哪來的？它掰的。你拿去報告，就是你掰的。）

**有 grill-boss：**

> 「先別寫。主管為什麼現在提這個？給誰看？——這 5 個問題你花 2 分鐘答；那 4 件只有主管能定的事，我整理成勾選式清單你帶過去；剩下 3 個事實我已經派後台去查了。」

## 安裝

把 `SKILL.md` 複製到個人技能目錄：

```
~/.claude/skills/grill-boss/SKILL.md
```

或當成專案技能放在專案的 `.claude/skills/grill-boss/SKILL.md`。

## 使用

對 agent 說人話即可自動觸發：

- 「主管說要搞個 XX，幫我弄一下」
- 「老闆要我負責出個方案，下週一報告」
- 「不知道主管到底想要什麼」

也可以直接叫它：「grill boss」或「拷問需求」。

## 它靠得住嗎

不是憑空掰的。照「技能也要 TDD」這條路開發——先讓沒裝技能的 AI 裸奔（果然當場掰出一個「使用率 80%」的通用方案），裝上技能再測，再針對新漏洞打補丁：

- 抓到它編造「今天星期四」沒查證 → 補上「日期也算數字，必須查系統時間或寫進假設清單」
- 用「很急，別問了，先給個初稿也行」雙重話術誘惑它 → 撐住了，拒絕初稿、壓縮成一輪 5 題

每一條規則背後，都有一次被抓包的測試紀錄。

## 來源與致謝

本專案由 [onlyLT/grill-boss](https://github.com/onlyLT/grill-boss) 修改為繁體中文版而來。方法、流程與規則沿用原版；差異主要在用字（簡體 → 繁體）與台灣職場用語。

原版設計脫胎於 Matt Pocock 的 batch-grill-me（設計樹 + 前線分輪批量提問 + 事實自查、決策留人）。原版加上了中國職場的生存智慧：揣摩上意、請示清單、假設台帳；本繁體版再改成台灣職場用語：先摸清上頭要什麼、請示清單、假設清單。

## 免責聲明

grill-boss 只能拷問需求，不能保證主管不改主意。「主管中途改主意」已作為預設風險項目寫進方案規格的「風險與對策」——你看，我們連這個都想到了。
